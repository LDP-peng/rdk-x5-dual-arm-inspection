## 3. C30D 串口协议分析

### 3.1 反馈帧

C30D 反馈帧固定为 24 字节：

| 偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 1 | 帧头 `0x7B` |
| 1 | 1 | 标志字节 `flag` |
| 2 | 2 | `vx_mm_s`，有符号 int16，大端 |
| 4 | 2 | `vy_mm_s`，有符号 int16，大端 |
| 6 | 2 | `wz_mrad_s`，有符号 int16，大端 |
| 8 | 2 | `ax_raw`，有符号 int16，大端 |
| 10 | 2 | `ay_raw`，有符号 int16，大端 |
| 12 | 2 | `az_raw`，有符号 int16，大端 |
| 14 | 2 | `gx_raw`，有符号 int16，大端 |
| 16 | 2 | `gy_raw`，有符号 int16，大端 |
| 18 | 2 | `gz_raw`，有符号 int16，大端 |
| 20 | 2 | `voltage_mv`，按协议解析 |
| 22 | 1 | 前 22 字节的 XOR-BCC |
| 23 | 1 | 帧尾 `0x7D` |

验证时使用过的一帧数据：

```text
7b 00 00 00 00 00 00 00 00 ff d4 00 10 40 03 ff fd 00 04 ff fe 31 38 0d 7d
```

解析结果：

```text
flag=0
vx=0
vy=0
wz=0
ax=-44
ay=16
az=16387
gx=-3
gy=4
gz=-2
voltage_mv=12600
```

### 3.2 速度命令帧

C30D 命令帧固定为 11 字节：

| 偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 1 | 帧头 `0x7B` |
| 1 | 1 | 固定 `0x00` |
| 2 | 1 | 固定 `0x00` |
| 3 | 2 | `vx_mm_s`，有符号 int16，大端 |
| 5 | 2 | `vy_mm_s`，有符号 int16，大端 |
| 7 | 2 | `wz_mrad_s`，有符号 int16，大端 |
| 9 | 1 | 前 9 字节的 XOR-BCC |
| 10 | 1 | 帧尾 `0x7D` |

100 mm/s 前进命令示例：

```text
7b 00 00 00 64 00 00 00 00 1f 7d
```

### 3.3 当前采用的底盘策略

- 使用反馈帧中的 `vx`、`wz` 做轮式里程计积分。
- 目前没有在 24 字节反馈帧中找到编码器计数，因此 `/odom` 是速度积分里程计，不是高精度编码器里程计。
- IMU 使用反馈帧中的加速度和角速度原始值。
- `/imu/data` 的 orientation 当前由角速度积分得到偏航角，只适合初始可视化和调试，不作为高精度绝对姿态源。
- 驱动内部使用 20 Hz 命令发送和 20 Hz 状态发布。
- 命令超时时间为 0.3 秒，超过时间没有新的 `/cmd_vel` 就自动停车。
- 默认限速：最大线速度 `0.25 m/s`，最大角速度 `0.8 rad/s`。

## 4. 新增 `robot_base` ROS2 包

### 4.1 目录

```text
robot_ws/src/robot_base/
├── config/
│   └── base.yaml
├── launch/
│   └── base.launch.py
├── robot_base/
│   ├── c30d_protocol.py
│   └── c30d_driver.py
├── package.xml
└── setup.py
```

### 4.2 各文件作用

| 文件 | 作用 |
|---|---|
| `c30d_protocol.py` | 构造命令帧、解析反馈帧、从串口字节流中提取完整帧 |
| `c30d_driver.py` | ROS2 节点，打开串口、接收 `/cmd_vel`、发布 `/odom` 和 `/imu/data`、广播 TF |
| `config/base.yaml` | 串口、话题、坐标系、频率、限速、超时和原始 IMU 比例参数 |
| `launch/base.launch.py` | 启动 `c30d_driver`，支持通过 `port:=...` 覆盖串口 |

### 4.3 对外的 ROS2 接口

订阅：

```text
/cmd_vel    geometry_msgs/msg/Twist
```

发布：

```text
/odom       nav_msgs/msg/Odometry
/imu/data   sensor_msgs/msg/Imu
```

TF：

```text
odom -> base_footprint
```

### 4.4 默认参数

```yaml
c30d_driver:
  ros__parameters:
    port: "/dev/wheeltec_controller"
    baud_rate: 115200
    cmd_vel_topic: "/cmd_vel"
    odom_topic: "/odom"
    imu_topic: "/imu/data"
    odom_frame: "odom"
    base_frame: "base_footprint"
    imu_frame: "imu_link"
    command_rate: 20.0
    publish_rate: 20.0
    cmd_timeout: 0.30
    max_linear_speed: 0.25
    max_angular_speed: 0.80
    invert_linear: false
    invert_angular: false
    accel_lsb_per_g: 16384.0
    gyro_lsb_per_dps: 16.4
```

如果实测发现前进或转向方向相反，可以分别修改：

```yaml
invert_linear: true
invert_angular: true
```

## 6. udev 固定串口修复

### 6.1 问题现象

最初规则使用：

```udev
ATTRS{serial}=="5CF0016185"
```

执行 `ls -l /dev/wheeltec_*` 时报：

```text
No such file or directory
```

说明规则没有匹配到 CH9102 串口设备。

### 6.2 原因

CH9102 的序列号在 udev 环境中应以 `ENV{ID_SERIAL_SHORT}` 访问，旧规则使用 `ATTRS{serial}` 没有命中。

### 6.3 修复后的规则

板端文件：`/etc/udev/rules.d/99-wheeltec.rules`

```udev
SUBSYSTEM=="tty", KERNEL=="ttyACM*", ENV{ID_VENDOR_ID}=="1a86", ENV{ID_MODEL_ID}=="55d4", ENV{ID_SERIAL_SHORT}=="5CF0016185", MODE:="0660", GROUP:="dialout", SYMLINK+="wheeltec_controller"
SUBSYSTEM=="tty", KERNEL=="ttyACM*", ENV{ID_VENDOR_ID}=="1a86", ENV{ID_MODEL_ID}=="55d4", ENV{ID_SERIAL_SHORT}=="0001", MODE:="0660", GROUP:="dialout", SYMLINK+="wheeltec_lidar"
```

重新加载：

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger --action=add --subsystem-match=tty
sudo udevadm settle
ls -l /dev/wheeltec_*
```

### 6.4 验证结果

```text
/dev/wheeltec_controller -> ttyACM1
/dev/wheeltec_lidar      -> ttyACM0
```

这样即使以后重新插拔 USB，只要序列号不变，设备别名就不会随 `ttyACM` 编号变化而交换。

- `odom -> base_footprint` 能查到。
- 静止时速度接近 0。

### 9.5 低速前进测试

```bash
timeout 2 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 0.05}, angular: {z: 0.0}}"
```

观察：

- `linear.x > 0` 时，轮子应向前转。
- 命令停止后，驱动应在约 0.3 秒内自动停车。

如果方向相反，修改 `robot_ws/src/robot_base/config/base.yaml`：

```yaml
invert_linear: true
```

然后重启 `robot_base`。

### 9.6 低速转向测试

```bash
timeout 2 ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 0.0}, angular: {z: 0.3}}"
```

观察：

- `angular.z > 0` 时，机器人应向左转，也就是逆时针转。
- 如果方向相反，设置：

```yaml
invert_angular: true
```

### 9.7 常见问题

如果启动时报串口权限错误：

```bash
groups
ls -l /dev/ttyACM1
```

确认当前用户属于 `dialout` 组。若不属于：

```bash
sudo usermod -aG dialout sunrise
```

之后需要重新登录或重启板子。

如果 `/odom` 没有数据：

- 确认 `robot_base` 终端没有串口打开错误。
- 确认使用的是 `/dev/wheeltec_controller` 或 `/dev/ttyACM1`。
- 确认底盘控制板供电正常。
- 确认波特率是 115200。

如果 TF 查不到：

- 确认终端 1 的 `robot_description` 正在运行。
- 确认 `robot_state_publisher` 没有报 URDF 错误。

## 11. 重要决策与风险

### 11.1 不依赖 WHEELTEC 完整镜像

当前决定保留官方 RDK X5/TROS 环境，底盘控制由项目自己的 `robot_base` 包完成。

WHEELTEC ROS2 工作空间仍然有参考价值，尤其是：

- 底盘参数。
- 雷达和相机启动方式。
- Nav2 配置。
- 机器人模型和标定数据。

但它不是运行本项目的必要条件，也不建议直接把未验证的 WHEELTEC 镜像整体刷到当前板子上。

### 11.2 不要同时启动两套底盘控制

不要同时运行：

- WHEELTEC 的 `turn_on_wheeltec_robot`。
- 本项目的 `robot_base`。

两者都可能占用同一个串口并向底盘发送速度命令，容易造成冲突。

### 11.3 当前 `robot_bringup` 不可直接用

`robot_ws/src/robot_bringup/launch/robot.launch.py` 仍然引用：

- `turn_on_wheeltec_robot`
- `wheeltec_ekf`
- `usb_cam`

这些包在当前板子上不存在，所以该 launch 文件需要后续重构为：

- `robot_base`
- 本项目 URDF
- `hobot_usb_cam` 或已安装的 `usb_cam`
- N10P 驱动

### 11.4 里程计和 IMU 精度限制

- 当前 `/odom` 来自底盘反馈速度积分，不是编码器计数里程计。
- 长时间运行会有累计误差。
- `/imu/data` 的 orientation 是角速度积分偏航角，不是绝对姿态。
- 初期可以用于可视化和低速测试，不能直接作为高精度定位依据。

### 11.5 安全

- 第一次运动测试必须架空轮子。
- 后续落地测试必须限制速度并保留物理急停。
- 串口命令超时只有 0.3 秒，但仍不能替代硬件急停。
