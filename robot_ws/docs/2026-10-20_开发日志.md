## 2. `lslidar_driver` 编译：从失败到成功

### 2.1 第一轮失败：缺依赖

报错集中在 `pcl_conversions`。补装：

```bash
sudo apt install -y ros-humble-pcl-conversions ros-humble-pcl-ros \
  libpcl-dev libpcap-dev libyaml-cpp-dev libboost-thread-dev
```

### 2.2 第二轮失败：卡在 72%，20 分钟后手动中断

现象：

- 进度停在 `72%` 长达 12 分钟不动。
- 期间新开 SSH 标签页白屏，`ping` 正常（4/4，4~40 ms），22 端口也通，但 SSH 卡在 banner exchange。
- 板子整机响应慢到几秒一次。

诊断数据（`uptime` / `free -h` / thermal / `ps`）：

| 指标 | 数值 | 判读 |
|---|---|---|
| 内存 | `total 3.0Gi`，`Swap 0B` | 物理内存小，且没有交换区 |
| 温度 | `thermal-cpu 65.4°C`、`thermal-ddr 66.6°C` | 正常，不是过热降频 |
| `kswapd0` | CPU 8.3%，已运行 19 分钟 | 内核在疯狂回收内存 |
| 残留进程 | `colcon build` 已跑 23 分钟 | 中断没杀干净，继续抢内存 |

结论：`-j4` 同时编 4 个含 PCL / Eigen 重模板的 `.cpp`，峰值内存超过 3 GB 物理内存，内核进入直接回收（direct reclaim），整机（包括 SSH）被拖死。进度"卡住"不是慢，是在等内存。

### 2.3 解决方案

1. 清理残留进程：

```bash
pkill -f 'colcon build'
pkill -f cc1plus
```

2. 加 2 GB swap（本次编译可用；永久化需写 `/etc/fstab`，暂未做）：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

3. 降优化等级（`CMakeLists.txt` 里 `CMAKE_CXX_FLAGS_RELEASE`）：`-O3` → `-O1`。
4. 单线程编译，并打开逐文件日志：

```bash
cd ~/robot_ws
rm -rf build/lslidar_driver install/lslidar_driver
source /opt/tros/humble/setup.bash
MAKEFLAGS=-j1 colcon build --symlink-install --packages-select lslidar_driver \
  --parallel-workers 1 --event-handlers console_direct+
```

结果：**8 分 28 秒通过**，`Summary: 1 package finished [8min 28s]`。

### 2.4 编译告警说明

```
** WARNING ** io features related to pcap will be disabled
```

这是网络回放（PCAP）功能被裁掉，本项目用串口雷达，不影响。

## 4. C70 相机验证

### 4.1 设备能力

```bash
v4l2-ctl -d /dev/video0 --list-formats-ext
```

支持 `MJPG 640x480@30`、`MJPG 1280x720@30`，以及 `YUYV` 各档（720p 只有 10 fps）。`/dev/video1` 不使用。

抓流自检（不依赖 ROS）：

```bash
v4l2-ctl -d /dev/video0 --set-fmt-video=width=640,height=480,pixelformat=MJPG \
  --stream-mmap --stream-count=10
```

输出 `<<<<<<<<<<` 即 10 帧正常。

### 4.2 用官方 `hobot_usb_cam`

板端自带 `hobot_usb_cam`（硬件解码，CPU 占用低），官方 launch 的默认参数是 `/dev/video8` 和 `960` 宽，**必须显式覆盖**：

```bash
ros2 launch hobot_usb_cam hobot_usb_cam.launch.py \
  usb_video_device:=/dev/video0 \
  usb_pixel_format:=mjpeg \
  usb_image_width:=640 \
  usb_image_height:=480 \
  usb_framerate:=30 \
  usb_frame_id:=camera_link
```

### 4.3 结果与坑

- `/image` 是 `sensor_msgs/msg/CompressedImage`，`format: jpeg`，30 Hz。
- 因此 `ros2 topic echo /image --field width` 会报 `'CompressedImage' object has no attribute 'width'`，**这不是故障**。
- 驱动直接转发相机 MJPEG，不消耗解码 CPU。
- 后续做视觉需要原始图时再加转换：

```bash
ros2 run image_transport republish compressed raw \
  --ros-args -r in/compressed:=/image -r out:=/image_raw
```

- `Camera calibration file: [] does not exist` 是没填标定路径，`/camera_info` 仍会发但不准；做测距/AprilTag 前需要标定。

## 6. `/dev/wheeltec_controller` 丢失排查

### 6.1 现象

启动全栈后 `c30d_driver` 报 `[Errno 2] No such file or directory: /dev/wheeltec_controller`，`/odom`、`/cmd_vel`、`/imu/data` 全无，TF 里 `odom` 不存在。

### 6.2 定位

```bash
ls -l /dev/ttyACM* /dev/wheeltec_*
dmesg | tail -n 30
```

`dmesg` 里只有雷达（`1a86:55d4`，`SerialNumber=0001`）和摄像头（`0bda:3031`），**没有 C30D 的 `5CF0016185`**。说明底盘板根本没被 USB 枚举，属于硬件/供电层面，不是 udev 规则问题。

### 6.3 解决

检查底盘电源与 USB 线后，设备重新出现：`1a86:55d4`、`SerialNumber=5CF0016185`、`cdc_acm ... ttyACM1`。随后补建符号链接：

```bash
sudo cp ~/robot_ws/src/robot_bringup/udev/99-wheeltec.rules /etc/udev/rules.d/99-wheeltec.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=tty --action=add
ls -l /dev/wheeltec_*
```

得到 `wheeltec_controller -> ttyACM1`、`wheeltec_lidar -> ttyACM0`。

### 6.4 经验

- 两个 CH9102 的 VID/PID 完全相同（`1a86:55d4`），只能靠 `ID_SERIAL_SHORT` 区分。
- 符号链接不存在时，先看 `dmesg` 里设备到底有没有枚举；没枚举就去查线/电源，不要先怀疑 udev。
- `ttyACM*` 编号会变，正式运行一律用符号链接，临时可用 `base_port:=/dev/ttyACM1` 顶一下。

## 8. 今天遇到的“假故障”

这些现象看起来像故障，其实都不是，记录下来避免以后重复排查：

| 现象 | 真实原因 |
|---|---|
| `ros2 topic echo /image --field width` 报没有 width | `/image` 是 `CompressedImage`，没有 width 字段 |
| `timeout 4 ros2 topic hz` 没输出、显示 `Terminated` | 4 秒太短（DDS 发现 1~2 s + 统计窗口 1 s），加管道缓冲 |
| 新标签页 `ros2: No such file or directory` | 没有 `source` 环境 |
| 粘贴命令变成 `$'\E[200~timeout': command not found` | 终端括号粘贴控制码；`bind 'set enable-bracketed-paste off'` |
| `c30d_driver` exit code 1 + `RCLInvalidError: rcl_shutdown already called` | 收到 SIGINT 后，`main()` 的 `finally` 又调了一次 `rclpy.shutdown()`，是“收尸”阶段的二次异常 |
| `/odom` 突然没有发布者 | launch 窗格被 Ctrl+C 误杀，不是驱动崩溃 |

**教训**：launch 一律后台跑，测试命令单独开窗格：

```bash
nohup ros2 launch robot_bringup robot.launch.py > /tmp/bringup.log 2>&1 &
# 停止
pkill -f "ros2 launch robot_bringup"
```
