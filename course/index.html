01

ROS2 世界观：它到底在解决什么

机器人软件为什么需要“节点 + 通信 + 工具链”

 核心15 min
理解ROS2 不是操作系统内核，而是机器人软件的通信与工具框架。
分清节点、话题、服务、动作、参数各自适合什么场景。
说出ROS1 的 Master 架构与 ROS2 的 DDS 去中心化架构差异。

节点 Node

一个独立进程，负责一件小事，例如读雷达、算避障、控底盘。节点之间通过接口通信。

话题 Topic

发布/订阅，异步、多对多。适合持续数据流：/scan、/odom、/image_raw。

服务 Service

请求/响应，一对一、短任务。适合“查一次状态”“触发一次校准”。

动作 Action

目标 + 反馈 + 结果，可取消。适合“移动到目标点”“机械臂执行一段轨迹”。

参数 Parameter

节点的配置字典。速度、阈值、目标点都可以做成参数，启动时覆盖。

DDS

ROS2 的中间件。负责节点发现、数据分发和 QoS 策略，不需要中心 Master。

terminal · 最小发布订阅

ros2 run demo_nodes_cpp listener

环境搭建：Ubuntu、Humble 与 RDK X5

ROS2 Humble

Ubuntu 22.04 的长期支持版本，生态最全。普通电脑、虚拟机、RDK 上都以它为主。

TROS Humble

ROS_DOMAIN_ID

同一局域网内，只有 Domain ID 相同的节点才能互相发现。多机调试时先统一它。

ros2 doctor

环境体检工具，检查网络、RMW、平台和依赖问题。排障第一步。

src

build / install / log

04

节点：机器人系统的最小工作单元

一个节点只做一件事，然后通过接口和别人协作

 核心30 min
写出一个最小 rclpy 节点，理解 init / spin / destroy 的生命周期。
使用命名空间、重映射和 ros2 node info 排查节点。
避免在回调里做重活，理解执行器与回调组的意义。

一个节点一件事

雷达驱动、避障决策、底盘控制、机械臂控制应拆成不同节点。拆开后才能单独测试和替换。

命名空间

/robot1、/robot2 可以隔离两台设备的同名话题，避免互相干扰。

重映射

启动时把 /cmd_vel 改成 /robot1/cmd_vel，不改代码就能适配不同机器人。

回调与执行器

回调里只做轻量处理；耗时任务交给线程、定时器或独立节点，避免阻塞订阅。

python · 最小节点
import rclpy
from rclpy.node import Node

class HelloNode(Node):
    def __init__(self):
        super().__init__('hello_node')
        self.create_timer(1.0, self.tick)

    def tick(self):
        self.get_logger().info('hello robot')

def main():
    rclpy.init()
    node = HelloNode()
    try:
        rclpy.spin(node)
    finally:
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
terminal · 观察节点
ros2 node list
ros2 node info /hello_node
ros2 run my_first_pkg hello --ros-args -r __ns:=/robot1
练习：把节点放到 /robot1 命名空间，观察 ros2 node list 的名称变化；再用 ros2 node info 看它发布了哪些话题。
05

话题：机器人数据流的高速公路

发布/订阅、消息类型、QoS，以及怎么判断数据是否正常

 核心35 min
写一个发布者和一个订阅者，理解消息类型必须一致。
诊断用 topic list / echo / hz / info 判断话题是否在发、频率对不对。
选择传感器数据使用 SensorDataQoS，普通控制数据使用默认可靠 QoS。

异步、多对多

一个发布者可以有多个订阅者，一个订阅者也可以听多个发布者。发布者不关心谁在听。

消息类型

std_msgs/msg/String、geometry_msgs/msg/Twist、sensor_msgs/msg/LaserScan。类型不匹配就收不到。

QoS

可靠性、历史深度、持久性。雷达和相机常用 Best Effort；底盘控制常用 Reliable。

常见话题

/scan 雷达、/odom 里程计、/cmd_vel 速度指令、/image_raw 图像。

python · 发布 /cmd_vel
from geometry_msgs.msg import Twist

self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
msg = Twist()
msg.linear.x = 0.1
msg.angular.z = 0.0
self.pub.publish(msg)
terminal · 话题诊断
ros2 topic list -t
ros2 topic echo /odom --once
ros2 topic hz /scan
ros2 topic info /scan --verbose
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.1}}" -r 10
练习：启动雷达后执行 ros2 topic hz /scan，记录频率；再执行 ros2 topic info /scan --verbose，看发布者数量与 QoS。
06

服务、动作与接口：让机器人“执行一件事”

短任务用服务，长任务用动作，接口定义是契约

 核心40 min
区分服务与动作：是否需要进度反馈、是否能取消。
调用现有服务与动作，读懂 .srv / .action 定义。
设计一个自定义接口，知道消息包应独立于业务包。

Service

客户端发请求，服务端处理后返回。适合查询、校准、切换模式等短操作。

Action

客户端发目标，服务端持续反馈进度，最后返回结果；中途可以取消。

接口定义

.msg 描述数据，.srv 用 --- 分隔请求与响应，.action 分目标、反馈、结果。

接口包

把自定义消息放在独立的 xxx_interfaces 包里，避免业务包互相依赖。

terminal · 服务与动作
ros2 service list -t
ros2 service call /spawn turtlesim/srv/Spawn "{x: 2.0, y: 2.0, theta: 0.0, name: 'turtle2'}"

ros2 action list -t
ros2 action send_goal /turtle1/rotate_absolute turtlesim/action/RotateAbsolute "{theta: 1.57}" --feedback
interface · 自定义服务
# SetMode.srv
string mode
---
bool success
string message
练习：用服务在 turtlesim 里生成第二只乌龟，再用动作让它旋转 90°；观察 --feedback 输出的过程。
07

参数、Launch 与 TF：把系统配置和坐标理清

启动参数、批量启动、坐标变换，是工程化的分水岭

 进阶45 min
参数化把目标点、速度、阈值从代码里拿出来，启动时覆盖。
写 Launch一次启动多个节点，并传入参数和命名空间。
理解 TFmap → odom → base_link → laser 的坐标链。

参数声明

先 declare_parameter 再 get_parameter；启动时用 --ros-args -p name:=value 覆盖。

Launch 文件

Python 描述启动逻辑：启动哪些节点、传什么参数、开什么命名空间、失败怎么处理。

TF2

维护坐标系之间的变换。雷达看到的点，必须通过 TF 转到车体或地图坐标才有意义。

URDF

用 link 和 joint 描述机器人结构；robot_state_publisher 根据关节角发布 TF。

python · 声明参数
self.declare_parameter('target_x', 2.0)
self.declare_parameter('front_stop', 0.50)
self.target_x = self.get_parameter('target_x').value
self.front_stop = self.get_parameter('front_stop').value
python · 最小 Launch
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        DeclareLaunchArgument('target_x', default_value='2.0'),
        Node(
            package='robot_mission',
            executable='mission',
            parameters=[{'target_x': LaunchConfiguration('target_x')}],
            output='screen',
        ),
    ])
terminal · TF 与 Launch

ros2 run tf2_ros static_transform_publisher --x 0 --y 0 --z 0 --yaw 0 --pitch 0 --roll 0 --frame-id map --child-frame-id base_link
ros2 run tf2_tools view_frames
练习：把避障距离 front_stop 做成参数，分别用 0.35 和 0.50 启动，观察小车在障碍物前停下的位置差异。
08

DDS、QoS 与分布式：节点为什么能自动发现

多机通信、数据可靠性、录包回放与排障

 进阶30 min
理解DDS 的自动发现机制，以及 Domain ID 为什么必须一致。
配置QoS：可靠性、历史深度、持久性，避免“有话题但收不到数据”。
掌握多机通信、ros2 bag 录包回放和 rqt_graph。

Domain ID

同一网段、同一 Domain ID 的节点才能发现彼此。多机调试先统一 ROS_DOMAIN_ID。

Reliability

Reliable 保证送达但可能重传；Best Effort 不重传，适合高频雷达和图像。

History / Depth

缓存最近多少条消息。控制指令 depth 不宜过大，否则会执行过期指令。

Durability

Transient Local 可以让晚加入的订阅者收到最后一条，例如地图、静态配置。

python · 传感器 QoS
from rclpy.qos import qos_profile_sensor_data
from sensor_msgs.msg import LaserScan

self.create_subscription(
    LaserScan, '/scan', self.on_scan, qos_profile_sensor_data
)

实战：把巡检、避障、机械臂串成一条链路

从启动外设，到目标点停车，再到机械臂动作与主从映射

 实战60 min

定位

避障

到点动作

主从映射

Hands-on Lab

实验手册：一条可复现的巡检链路

目标不是“看起来能跑”，而是每一步都有检查点。任何一步没通过，就停下来排查，不要带着问题往下走。

STEP 01 · 上电前

检查供电与接线

雷达、相机、底盘驱动板、机械臂扩展板分别确认供电；I2C 和 USB 不要带电插拔。

  • 雷达转起来，USB 已识别
  • 底盘驱动板与 RDK 通信正常
  • 机械臂扩展板独立供电
STEP 02 · 环境

加载 ROS2 / TROS

顺序很重要：先 TROS，再 ROS2，最后工作空间。

terminal
source /opt/tros/humble/setup.bash
source /opt/ros/humble/setup.bash
source ~/robot_ws/install/setup.bash
export ROS_DOMAIN_ID=0
STEP 03 · 外设

启动相机与图传

run_demo.sh 负责把相机服务拉起来，先确认两个画面都能打开。

terminal
bash ~/run_demo.sh
# 浏览器打开
# http://<板子IP>:8080
# http://<板子IP>:8081
STEP 04 · 验数据

先看话题，再跑任务

雷达、里程计、速度指令三项都正常，才说明系统具备闭环条件。

terminal
ros2 topic list -t
ros2 topic hz /scan
ros2 topic echo /odom --once
ros2 topic echo /cmd_vel --once
STEP 05 · 巡检

目标点 + 雷达避障 + 到点动作

front_stop:=0.50 表示前方 0.5 米内停车并绕行；arm_demo:=true 表示到点后触发机械臂动作。

terminal · 一键复制
python3 ~/odom_mission.py --ros-args \
  -p target_x:=2.0 -p target_y:=0.0 -p target_yaw:=0.0 \
  -p max_linear:=0.08 -p front_stop:=0.50 \
  -p avoid_turn_deg:=75.0 -p front_half_angle:=0.45 \
  -p arm_demo:=true

自动动作与主从遥操作分开测

先单独验证机械臂动作，再打开主臂映射。不要同时改动作脚本和映射参数，否则出问题无法定位。

FAQ

入门阶段最容易卡住的地方

这些问题通常不是“代码写错了”，而是环境、QoS、网络或坐标没对齐。

ROS1 和 ROS2 到底差在哪？我该学哪个？

ROS1 依赖中心 Master，ROS2 用 DDS 做去中心化发现；ROS2 还带来更好的多机、实时、QoS 和生命周期管理。新项目直接用 ROS2 Humble，ROS1 只在维护老设备时学。

ros2 topic list 看不到话题怎么办？

按顺序查：节点是否真的启动、当前终端是否 source 了环境、两台机器的 ROS_DOMAIN_ID 是否一致、是否在同一网段、QoS 是否兼容。最后再看 ros2 node info 里节点到底有没有发布。

雷达有 /scan，但避障节点收不到？

最常见是 QoS 不匹配。雷达常用 Best Effort，订阅端如果用默认 Reliable 会收不到。用 ros2 topic info /scan --verbose 对比两端的 Reliability 和 Durability。

两块板子/两台电脑怎么通信？

同一局域网、同一 ROS_DOMAIN_ID、ROS_LOCALHOST_ONLY=0，并放行组播或配置单播。先用 ros2 doctor 和 ros2 node list 验证发现，再传大流量图像。

SLAM 建图和雷达避障是一回事吗？

不是。SLAM 解决“我在哪、环境长什么样”，输出地图和位姿；避障解决“前面有没有东西、现在怎么绕”。空旷现场可以不建图，直接用里程计 + 前向雷达做短距离任务。

RDK X5 上为什么很多命令和教程不一样？

RDK 用的是 TROS，多了 BPU、摄像头和地平线扩展包，但底层仍是 ROS2 Humble。先 source /opt/tros/humble/setup.bash，再 source 普通 ROS2，绝大多数命令通用。
